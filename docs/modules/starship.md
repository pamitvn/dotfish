# starship — Starship cross-shell prompt

With this Module on, the plain fish prompt is replaced by a two-line
[Starship](https://starship.rs) prompt: the first line shows who and where you
are (`╭─user@host in ~/some/dir`), your git branch, status, and last
commit/tag, plus how long the previous command took; the second line is the
`╰─λ` you type at. Language and tool versions (node, php, python, go, …)
appear automatically when you're in a matching project.

## Get it / remove it

Install: picked **by default** in the `dotfish` picker, or explicitly with
`dotfish --modules starship,...`. If the `starship` binary is missing, the
Installer fetches it with the official install script
(`curl -sS https://starship.rs/install.sh | sh -s -- -y`).

Remove: re-run `dotfish` and deselect it (or pass `--modules ...` without
`starship`) — both the Module's fish snippet and its `~/.config/starship.toml`
are removed together, and the prompt falls back to fish's default.

Remember the install is a Snapshot copy: editing the Module's files (including
`~/.config/starship.toml`) directly gets overwritten on the next `dotfish`
run. Machine-local tweaks belong in `profile.local.fish`.

## What it changes in your shell

No aliases or new commands — the Module changes the prompt itself:

- In every interactive shell, Starship is initialized and takes over the
  prompt (non-interactive shells and scripts are untouched).
- A prompt config is installed at `~/.config/starship.toml` (or
  `$XDG_CONFIG_HOME/starship.toml`).
- Tab completion for the `starship` command is registered (generated by Core).

What the installed config gives you, line by line:

| Prompt element | What you see |
|---|---|
| Username & host | `╭─user@host` — always shown, root in bold red |
| Directory | Purple path, truncated to the repo root (`repo: ...`) inside git repos |
| `sudo` indicator | Shown when sudo credentials are cached |
| Git branch / status | ` branch`, with `⇡n`/`⇣n` ahead/behind counts, `⇕` when diverged, `x` for deletions |
| Git commit & tag | Last commit ID and current tag in bold blue — the tag shows even on a branch |
| Command duration | `took 3s` for anything slower than 1 ms |
| Prompt character | `╰─λ` on success, `×` after a failing command |
| Exit status | `[🔴 …]` with the exit code's common meaning and signal name; per-command `pipestatus` for pipelines |
| Language versions | Nerd Font symbols for node, php, python, go, rust, java, ruby, docker context, nix shell, and more |

The battery and clock modules are present in the config but disabled.

## Usage

```fish
# Inside a git repo: branch, ahead/behind arrows, and the last commit/tag
# appear in the first prompt line automatically
cd ~/projects/my-app

# A slow command reports its duration in the prompt
sleep 3   # → ... took 3s

# A failing command flips the prompt character and shows the status
false     # → × ... [🔴1 ERROR]
```

The prompt uses Nerd Font glyphs for its symbols — use a Nerd Font-patched
terminal font or the language icons render as boxes.

## Tweaks & opt-outs

- **Change the prompt layout?** Don't edit `~/.config/starship.toml` in place —
  it's part of the Snapshot copy and the next `dotfish` run overwrites it.
  Keep a machine-local config elsewhere and point Starship at it from
  `profile.local.fish`:

  ```fish
  # profile.local.fish
  set -gx STARSHIP_CONFIG ~/.config/starship.local.toml
  ```

- **starship not installed?** The snippet guards on `type -q starship`, so
  without the binary nothing is initialized and you keep the standard fish
  prompt — the Module degrades silently rather than breaking your shell.
